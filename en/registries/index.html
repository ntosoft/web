AREAS OF INTEGRATION

Connecting to registries and national services

An overview of the areas where our software communicates with the national healthcare infrastructure, including the protocol we use and what we handle for the facility.

AREAS OF INTEGRATION

What we can connect

Master registries

Patient lookup and identification, verification of providers and healthcare staff, subscriptions to change notifications. Work with RID and temporary RID during outages.

Infectious disease reporting

Automated reporting from outpatient care, inpatient care and laboratories through REST APIs. Creating, updating and cancelling reports, status code handling and permission checks.

National registries and data collection

Submitting data to national health registries, including inpatient facility reports, screening programmes and centre-based treatment. Code system validation before sending.

Electronic prescription

Issuing, retrieving and dispensing electronic prescriptions and vouchers via the central repository. Communication over SOAP and WSDL, preparation for verification test scenarios.

Shared health records

Patient summary, discharge report, laboratory and imaging reports and electronic requests in HL7 FHIR R4 following the Czech implementation guides.

Base registries and identity

Identity matching and processing of change notifications where required by the agenda, plus work with national identity for user sign-in.

Health insurers

Reporting of care and batch exchange per the insurers' data interfaces, pre-submission checks and processing of feedback files.

Cross-border exchange

Preparing documents for cross-border exchange of health data within the EU and verifying interoperability against test scenarios.

ONBOARDING

How connecting works

Access to national services requires the facility to be registered and to hold certificates issued by the relevant authority. Each integration also goes through verification by the operator of the service, so we always split the process into four steps.

  1. Permissions and certificates

    We verify the provider's registration and help prepare documents for issuing certificates.

  2. Test environment

    Development and debugging run against the operator's test interfaces with test data.

  3. Operator verification

    We run through the service's test scenarios and demonstrate correct communication.

  4. Production

    We deploy the integration, enable monitoring and watch certificate validity and specification changes.

FROM PRACTICE

What we watch for in integrations

Most problems do not show up on the first successful call but in operation. These are topics we address in every project.

Certificate expiry

An expired certificate stops all communication at once, often at the worst possible moment. We monitor validity automatically, plan renewal ahead and verify it in a test environment.

Test versus production

A test environment does not have the same data, the same load or always the same behaviour as production. We therefore separate configuration, service addresses and certificates so test data can never be sent to a live system by mistake.

Specification changes

National interfaces evolve: fields are added, code lists change, new versions appear. We therefore version our interfaces, follow operators' announcements and roll out changes so older clients keep working.

Duplicates and record merging

One patient can have several records in different systems, and identifiers change after matching. We design the data model so that merging and identity correction do not break linked documentation.

Working during outages

A practice cannot stop treating patients because a central service is unavailable. We therefore queue requests, work with temporary identifiers and send them in the correct order with duplicate checks once the connection is restored.

Personal data in logs

Technical logs quickly become a hidden copy of sensitive data. We therefore do not write message content or identifying data to regular logs, only meaningless request identifiers, and protect more detailed records separately.
